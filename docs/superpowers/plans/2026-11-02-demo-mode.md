# Demo Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** An in-app demo mode — entered from a first-launch modal or Settings — where the whole app runs against a simulated gno.world and a simulated chain, in memory only, with a skippable step-by-step guide in pointed bubbles.

**Architecture:** `AppServices` already builds every dependency in one place. Demo mode builds the same `Services` object from in-memory parts: the existing fake gno.world (`scripts/fake-offchain/server.ts`) extracted into a platform-neutral core and wrapped as an `Offchain`; a new simulated v6 realm behind a `ChainApi`; a memory KV and secret store. A non-persisted `demoStore` holds "on/off", an epoch and the guide step; switching rebuilds `Services` and remounts the tree. The guide is a root overlay that points at `GuideTarget`-wrapped elements and advances on "Next" or on events the screens emit.

**Tech Stack:** Expo SDK 58, Expo Router, React Native, zustand, Jest (jest-expo) + RNTL 14, TypeScript.

**Spec:** `docs/superpowers/specs/2026-11-02-demo-mode-design.md`

## Global Constraints

- Node ≥ 22.13 (`ASDF_NODEJS_VERSION=22.23.2`); use `npx` (no `bun.lock`).
- No new dependency. Nothing under `ios/` or `android/`.
- New code lives in `src/demo-mode/` — **not** `src/demo/`: `package.json` jest `testPathIgnorePatterns` ignores any path containing `/demo/`.
- No `node:*` import and no `Buffer` in anything under `src/` (it is bundled for the phone).
- In demo: **no** `fetch`, **no** call on gnonative's API, **no** write to AsyncStorage or SecureStore except the key `br.demo.offered`, **no** write to `settingsStore`.
- Demo content is invented: no production name, address or message (not `jae`, not fixture lines, not real `g1…` addresses).
- User-facing text in English. Exact copy where this plan gives it.
- The real-mode behaviour of every screen is unchanged when demo is off.
- Done means: `npx expo lint` with zero errors and zero warnings, `npx tsc --noEmit` clean, `npx jest` green, `npm run e2e:chat`, `npm run e2e:pair`, `npm run e2e:rooms` green.
- Commits: `git commit -s`, conventional messages, on branch `feat/demo-mode`.

## Review Focus

1. The app goes to the background and back during demo — the chat long-poll, rooms scans, /pair sync and presence restart on the demo services and still send nothing. (Task 5 test `demo services survive background/foreground without network`.)
2. Leaving demo while a long-poll or a transaction is in flight — its late answer must not land in the real stores. (Task 6 test `a demo answer arriving after leaving does not reach the real chat`.)
3. A user with a real session, reserved name and rooms enters and leaves demo — all three are exactly as before, and the real session's `restore()` runs again. (Task 6 test `real session, name and rooms survive a demo round trip`.)
4. A malformed pair code in demo — the same `BAD_CODE` error as the real app, no fake pairing. (Task 3 test `a malformed code is refused like the real server`.)
5. A deep link during demo (pool link with `ref=`, a session callback) — no `settingsStore` write, and a callback's reply is ignored by the demo session (state mismatch). (Task 6 test `deep links during demo write no settings`.)
