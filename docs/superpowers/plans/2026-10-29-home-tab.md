# Home Tab Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A first tab, Home, that sums up gno.world like the site's home page: the GNOT price with a 1d/7d/30d chart, who is here by country, and the last chat lines (tap → Chat tab).

**Architecture:** Two read-only fetchers in `src/offchain/home.ts` (`/api/prices`, `/api/where`) on the existing `Offchain` client; pure formatting and chart geometry in `src/screens/home/`; one polling hook that runs only while Home is focused and the app is active; three cards composed in a `ScrollView` with pull to refresh. The chat card reads the chat store that already runs app-wide. Pools moves from `(tabs)/index` to `(tabs)/pools`; Home takes `index` and its `?ref=` handling.

**Tech Stack:** Expo SDK 58 (`expo` ~58.0.19), Expo Router 58 (typed routes on), React Native 0.88, TypeScript, zustand 5, react-native-svg 15.16 (already installed), Jest 30 (jest-expo), @testing-library/react-native 14 (async `render`/`fireEvent`), Node ≥ 22.13.

**Spec:** `docs/superpowers/specs/2026-10-29-home-tab-design.md` (French).

## Global Constraints

- Repo `~/bubblerumble`, branch `main`, local; commits with `git commit -s` (DCO). Nothing is pushed without the user's go-ahead.
- No new dependency. The chart is `react-native-svg`.
- All requests go through `services.offchain` (base URL from Settings, `X-Bid`). No request while the app is in the background or Home is not focused.
- Routes, verbatim: `GET /api/prices?coin=gnot&days=<1|7|30>`, `GET /api/where`.
- Site texts, verbatim: `nobody here right now`, `just you`, `<N> people`, ` · countries unavailable on this build`, `nobody yet`, `elsewhere`, `prices are busy — trying again`. Our text: `unknown` (the single row when `geo` is not true).
- Colours from `src/theme.ts`: chart and bars `colors.accent`; change ≥ 0 `colors.ring`, < 0 `colors.bad`; secondary text `colors.muted`.
- Tabs, in order: Home (label `Home`, header `gno.world`, icon `house.fill` / `home`), Pools, Chat, Session, Settings.
- Refresh: price every 300 000 ms and on a period change; where every 20 000 ms. After a failure: retry in 4 000 ms (first consecutive failure), then 20 000 ms, at most 8 consecutive retries, then back to the normal interval.
- Before "done": `npm test`, `npx tsc --noEmit`, `npx expo lint` with zero errors and zero warnings.
- Comments: short, saying why, as in the surrounding code.

## Review Focus

1. **A malformed or partial reply** (missing `series`, `null` numbers, `by_country` not an array): the card shows what it can and never crashes — pinned in Task 1.
2. **A series with fewer than 2 points or a flat price** (all points equal): no chart for < 2; a flat line in the middle, no division by zero — pinned in Task 2.
3. **Switching the period while a load is in flight**: the late reply of the old period must not overwrite the new one — pinned in Task 3.
4. **Leaving Home / backgrounding the app**: polling stops, and starts again on return — pinned in Task 3.
5. **An empty chat** (no lines yet, or the chat unreachable): the card still opens Chat and says so instead of being blank — pinned in Task 4.

### Task 3: Polling hook

**Files:**
- Create: `src/screens/home/use-poll.ts`, `src/screens/home/use-poll.test.tsx`

**Interfaces:**
- Consumes: `useFocusEffect` from `expo-router`; `AppState` from `react-native`.
- Produces:
  ```ts
  export interface Poll<T> { data: T | null; failed: boolean; refresh(): Promise<void> }
  /** Loads now and every `everyMs` while the screen is focused and the app active. A change of `key` drops the
   *  data and loads at once; a late reply for an older key is ignored. */
  export function usePoll<T>(load: () => Promise<T>, everyMs: number, key?: string): Poll<T>;
  export const RETRY_FIRST_MS = 4000, RETRY_NEXT_MS = 20000, RETRY_MAX = 8;
  ```

- [ ] **Step 1: Write the failing tests** with `jest.useFakeTimers()`, a `renderHook`, `expo-router` mocked so `useFocusEffect` runs its callback in a `useEffect` (and its cleanup on unmount), and `AppState.addEventListener` spied to capture the listener.
  - `loads at once, then every everyMs` — `load` called 1×, after `advanceTimersByTime(20000)` 2×.
  - `keeps the last data and sets failed on an error` — first load resolves `'a'`, second rejects → `data === 'a'`, `failed === true`; next success → `failed === false`.
  - `retries 4 s then 20 s, 8 times, then the normal interval` — `load` always rejects, `everyMs = 300000`: calls at 0, +4000, then +20000 each up to 9 calls in all; the 10th only after +300000.
  - `a new key drops the data and ignores the late reply of the old key` — key `'1'` load pending; rerender with key `'7'`; resolve the old promise with `'old'`, the new with `'new'` → `data === 'new'`; while the new one is pending `data === null`.
  - `stops in the background and on unmount, starts again when active` — listener(`'background'`) → no call after `advanceTimersByTime(60000)`; listener(`'active'`) → one immediate call; unmount → no further call.
  - `refresh loads now and resolves when done`.
- [ ] **Step 2: Run** `npx jest src/screens/home/use-poll.test.tsx` — Expected: FAIL.
- [ ] **Step 3: Implement `usePoll`.** One `setTimeout` chain (not `setInterval`) so the retry delay can differ from the interval; a generation counter (bumped on key change, blur, background, unmount) discards stale replies; no two chains at once (`'active'` can be reported twice — see the presence heartbeat in `src/state/app-services.tsx`).
